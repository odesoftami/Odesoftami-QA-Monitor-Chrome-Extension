Floating QA panel

A compact panel can stay over the monitored page in Monitor and QA Session modes. It reads the same session data as the dashboard and never creates a second monitoring engine.

The panel uses a Shadow DOM and the existing service worker/session data. Hiding or collapsing it never stops monitoring; only the explicit Stop action does.

Local data

Sessions, events, presets and screenshots stay in this browser profile. Nothing is sent to Odesoftami or any third party. Clearing completed session history does not delete stored screenshots.

Permissions and privacy

  • storage — local settings, sessions, events and presets.
  • activeTab — identifies the tab you explicitly monitor and supports opt-in screenshots of the active tab.
  • scripting — injects the monitoring script into an already-open tab when a session starts.
  • notifications — shows local alerts for configured conditions and failures.
  • alarms — wakes the service worker and provides a fallback when background tab timers are throttled.
  • webRequest — observe-only access to main-frame HTTP/HTTPS navigations while a session is running. Used solely to read the final status code, redirect target and network error; it never blocks or modifies requests. webRequestBlocking is not used.
  • HTTP/HTTPS host access — required to inject the monitor on the pages you choose and to read navigation results for them. It is not used to send data anywhere.

Cross-origin iframe content and closed shadow DOM cannot be inspected. HTTP status and timing may be unavailable for pages loaded before a session starts; those results are recorded as UNKNOWN, never as a fabricated 200.

Chrome may delay alarms under heavy system load or while the browser is sleeping; the interval is a target, not a real-time guarantee.
