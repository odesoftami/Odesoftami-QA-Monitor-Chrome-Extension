Privacy Policy

Odesoftami QA Monitor v3.2.0 · Denys Oleksiienko

Summary

Odesoftami QA Monitor is a local-first browser QA and monitoring extension. It does not collect, transmit, sell or share browsing data, page contents, QA logs or screenshots. There is no telemetry, no analytics, no advertising and no remote code. All monitoring data stays in your browser profile until you delete it.

What the extension stores locally

  • Settings — bypass cache, badge visibility, default mode, stabilization period, history limit and screenshot preference.
  • Session records — session ID, tab ID, mode, start/end times, stop reason, tested URL, expected URL and monitoring configuration.
  • QA events — timestamps, check type, PASS/FAIL/WARN/UNKNOWN result, the URL, expected and actual short values, HTTP status when Chrome exposes it, load duration in milliseconds, reasons and bounded technical details.
  • Text and DOM results — whether text or an element was found, and text lengths. The extension does not write full page contents to its event history. User-entered patterns, selectors and expected text are stored as configuration.
  • Presets — names, descriptions and check configuration that you save.
  • Floating-panel preferences — per-site panel position and collapsed state.
  • Screenshots (opt-in only) — captured only when you enable “Screenshot on failure”, only for the active, focused tab, and stored locally in IndexedDB. They are never uploaded.

URLs can contain query parameters. Treat exported reports and screenshots as potentially sensitive and store them accordingly. Exports are created locally by you and are not sent anywhere by the extension.

What the extension does not do

  • No network requests to Odesoftami or third parties.
  • No analytics, tracking, telemetry or advertising identifiers.
  • No collection of passwords, authentication tokens, cookies or form values.
  • No upload of screenshots, page text, browsing history or QA reports.
  • No remote executable code; all logic ships inside the extension package.
  • No inspection of Chrome internal pages, other extensions, cross-origin iframe content or closed shadow DOM.

Permissions and why they are needed

  • storage — saves settings, sessions, events, presets and floating-panel preferences in chrome.storage.local; active runtime state uses chrome.storage.session.
  • activeTab — identifies the tab you explicitly start monitoring and supports opt-in capture of the active tab.
  • scripting — injects the monitoring content script into an already-open tab at session start.
  • notifications — shows local desktop notifications for configured conditions and failures.
  • alarms — provides a service-worker-safe fallback timer and badge refresh when Chrome throttles background tabs.
  • webRequest — observe-only, main-frame-only access used while a monitored session is active to read the final HTTP status code, redirect target and network error. Requests are never blocked or changed; webRequestBlocking is not used.
  • Host access to HTTP/HTTPS pages — runs the monitor on pages you choose and reads navigation data. It is not used to transmit data.
  • Floating QA panel — UI-only, using the existing content script, storage and messaging. No additional permission is requested; panel position/collapsed state is local.

Retention and deletion

Event history is bounded per session (50–2,000 events; 500 by default, UI options 200/500/1,000/2,000), up to 30 sessions are retained, and screenshots are capped at 20 entries / 40 MB. Older records are pruned automatically. Clearing completed session history preserves active sessions, presets, settings and stored screenshots. Screenshots are removed only by the separate “Clear stored screenshots” action or individual deletion. You can delete individual sessions or presets in the dashboard. Removing the extension removes its extension storage and IndexedDB data according to Chrome's behavior.

Chrome Web Store data disclosure

The extension does not collect or transmit user data. Local storage exists only to provide the monitoring, history, preset and report features on your device. Because no data leaves the device, there is no third-party sharing, no data sale and no use of data for advertising, creditworthiness or lending. The optional GitHub and Web footer links are normal external hyperlinks; no request is made unless the user clicks one.
